# DJZS Engine — Replit Agent Prompt

## What you're building

A deterministic pre-trade audit engine for prediction markets (Polymarket, Kalshi) and crypto perpetuals (Hyperliquid via CoinGlass aggregation). The engine takes a structured trade thesis, runs it through typed failure-mode detectors, and returns a cryptographically-signed verdict (PASS / PASS_WITH_NOTES / ABORT / REVIEW) with a Keccak256-hashed receipt.

This is **not** a forecasting tool. It does not predict outcomes. It audits whether a thesis is structurally coherent, evidenced, and execution-ready before money moves.

## Non-negotiable architectural rules

These are load-bearing. Do not violate them without asking:

1. **Determinism is sacred.** `computeVerdict()` must be pure TypeScript with no LLM calls and no network calls. Same inputs → identical compute hash. The test suite enforces this.
2. **LLMs may flag inputs; LLMs do not decide verdicts.** Any semantic layer emits boolean flags only. All scoring happens in deterministic TS.
3. **Parse failures never trigger payment.** Unparseable theses return REVIEW with structured error codes. Only parseable theses reach the engine.
4. **Every external data source preserves source metadata** — `{provider, endpoint, fetched_at, response_hash, exchange_scope, freshness_window_seconds}` — attached to every receipt that used that data. This is how receipts stay defensible when aggregators change their feeds.
5. **canonicalJSON must preserve round-trip invariance.** Undefined values in objects are omitted (not serialized as null). Tests enforce this — do not "simplify" that function.
6. **Every new detector ships with:** implementation, minimum 3 unit tests (positive trigger, negative, edge case), an entry in `defaultDetectors()`, and works against the existing `EngineInput` / `LFTrigger` interfaces.
